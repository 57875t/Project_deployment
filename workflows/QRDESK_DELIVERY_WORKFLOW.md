# QR Desk Delivery Workflow

本项目所有重要改动都按下面六阶段执行，不允许跳过真实性和验收环节。

## 1. Preview

- 明确本轮目标、范围、输入、输出和不可触碰边界。
- 确认哪些数据必须是真实数据，哪些只能作为独立模拟模式存在。
- 标记外部依赖：API Key、行情权限、部署平台、域名、CORS。

## 2. Execute

- 在独立分支实现改动。
- 只提交本轮相关文件。
- 密钥只通过云端环境变量注入，绝不写进 HTML、日志或仓库。

## 3. Nitpick

重点找茬：

- 是否存在模拟值写入真实字段；
- 是否把延迟数据冒充实时数据；
- 是否在休市日生成不存在的当日 K 线；
- 是否存在时间戳、时区、复权、周期聚合错误；
- 是否在失败时静默回退为假数据；
- 是否暴露 API Key；
- 是否有不可复现的手工步骤。

## 4. Review

- 检查接口契约、代码差异、配置文件和错误分支。
- 对每个发现标记：`PASS`、`NEEDS FIX`、`OPEN` 或 `BLOCKED`。
- 不以“页面看起来正常”代替数据真实性检查。

## 5. Acceptance

最低验收：

- `/v1/market/health` 可访问；
- 至少一个供应商真实返回数据；
- US、HK、CN 各有代表性标的测试；
- 休市状态和最后有效 K 线表现正确；
- 错误 API Key 时返回结构化错误且无模拟回填；
- 浏览器网络请求中不出现供应商密钥；
- 前端展示 Provider、时效和来源标签。

## 6. Closure

- 更新 README、审计记录、任务清单和版本号；
- 只在所有关键门槛通过后将 PR 标记为 Ready；
- 未完成项必须留在 Issue 或审计文档中，不能口头带过。
