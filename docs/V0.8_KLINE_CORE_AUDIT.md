# QR Desk v0.8 — K-line Core Audit

## Mission

Make the displayed K-line and price-change fields converge on the licensed provider feed as closely as the provider entitlement permits.

“Calibration” in v0.8 means deterministic correction and validation of provider observations. It never means predicting, interpolating, or fabricating missing prices.

## Workflow

### 1. Preview

- Input: provider OHLCV bars and quote metadata.
- Output: normalized bars, exchange-session state, quality counters, price change, provenance and freshness.
- Hard boundary: real and simulated datasets remain physically and semantically separate.
- Calendar source: `exchange_calendars` using XNYS, XHKG and XSHG.

### 2. Execute

Implemented in phase 1:

- duplicate timestamp reconciliation;
- finite numeric and OHLC invariant validation;
- future timestamp rejection;
- deterministic 5-minute to 15-minute OHLCV aggregation;
- dedicated EOD path for daily bars;
- gap counting without gap filling;
- latest-bar freshness measurement;
- absolute and percentage change calculation;
- `syntheticBars: 0` provenance assertion.

Implemented in phase 2:

- exchange-local ISO date and datetime parsing;
- US, Hong Kong and mainland China exchange calendar mapping;
- trading-day, pre-open, open, lunch-break, post-close and non-session state;
- off-session bar removal;
- currently forming intraday bar removal;
- currently forming daily bar removal until the session has closed;
- lunch breaks, holidays, weekends and overnight closures excluded from gap counts;
- strict 5-minute to 15-minute aggregation that drops incomplete buckets;
- separate previous-session change and last-bar change fields;
- `marketSession`, calendar and bar-completeness counters added to the response.

### 3. Nitpick

Closed findings:

- **PASS:** HK and CN lunch breaks are no longer counted as missing data.
- **PASS:** weekend and holiday sessions cannot create a current-day candle.
- **PASS:** a currently forming candle is removed instead of displayed as complete.
- **PASS:** a 15-minute candle cannot be emitted from only one or two 5-minute records.
- **PASS:** naive provider timestamps are interpreted using the instrument exchange timezone.
- **PASS:** no gap interpolation or synthetic candle insertion exists.

Known risks still open:

- Provider timestamp conventions must still be live-verified as bar-start versus bar-end.
- Some providers may timestamp hourly partial session bars differently around lunch or close.
- Corporate-action adjustment settings can differ between providers.
- “Real-time” depends on the purchased entitlement and must never be inferred from a successful HTTP response alone.
- Shenzhen instruments currently use the XSHG trading calendar because the supported library exposes Shanghai as the mainland cash-equity calendar; live schedule equivalence still needs acceptance evidence.

### 4. Review

Current verdict: **PARTIAL PASS**

Passed:

- no synthetic gap filling;
- no future bars;
- deterministic and strict aggregation;
- exchange-session filtering;
- incomplete latest-bar filtering;
- lunch-break-aware and holiday-aware gap audit;
- explicit quality and market-session output;
- previous-session change separated from last-bar change;
- daily endpoint separated from intraday endpoint;
- focused local test suite: **9 passed**.

Open:

- provider timestamp convention verification with real responses;
- early-close and special-session live samples;
- corporate-action reconciliation;
- dual-provider cross-check;
- live entitlement and latency acceptance;
- final HTML wiring for `marketSession`, `quality`, `change` and `barChange`.

### 5. Acceptance

v0.8 may be marked LIVE PASS only when all are true:

- licensed provider credentials are configured outside the browser;
- returned symbol and exchange match the requested instrument;
- timestamp convention has been verified for US, HK and CN;
- market session, holiday, lunch-break and early-close logic are verified against live samples;
- latest completed bar is compared with the provider’s own UI or reference response;
- previous-close change and last-bar change match the same reference dataset;
- stale, delayed and real-time data are labeled correctly;
- provider failure produces no bars rather than simulated replacement bars;
- HTML displays the session state and quality verdict without hiding warnings.

## Closure status

Phase 2 code and deterministic tests are complete. The branch remains Draft because provider-backed live acceptance and HTML wiring are still open.
