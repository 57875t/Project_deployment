# QR Desk v0.8 — K-line Core Audit

## Mission

Make the displayed K-line and price-change fields converge on the licensed provider feed as closely as the provider entitlement permits.

“Calibration” in v0.8 means deterministic correction and validation of provider observations. It never means predicting, interpolating, or fabricating missing prices.

## Workflow

### 1. Preview

- Input: provider OHLCV bars and quote metadata.
- Output: normalized bars, quality counters, price change, provenance and freshness.
- Hard boundary: real and simulated datasets remain physically and semantically separate.

### 2. Execute

Implemented:

- duplicate timestamp reconciliation;
- finite numeric and OHLC invariant validation;
- future timestamp rejection;
- deterministic 5-minute to 15-minute OHLCV aggregation;
- dedicated EOD path for daily bars;
- gap counting without gap filling;
- latest-bar freshness measurement;
- absolute and percentage change calculation;
- `syntheticBars: 0` provenance assertion.

### 3. Nitpick

Known risks:

- Provider timestamps may use exchange-local time or UTC differently.
- Intraday gaps include legitimate lunch breaks, auctions and market closures unless exchange calendars are applied.
- A provider’s latest aggregate bar may still be forming.
- Corporate-action adjustment settings can differ between providers.
- “Real-time” depends on the purchased entitlement and must never be inferred from a successful HTTP response alone.

### 4. Review

Current verdict: **PARTIAL PASS**

Passed:

- no synthetic gap filling;
- no future bars;
- deterministic aggregation;
- explicit quality output;
- explicit price-change output;
- daily endpoint separated from intraday endpoint.

Open:

- exchange calendar/session engine;
- partial-bar detection by market and interval;
- provider timestamp convention verification;
- corporate-action reconciliation;
- dual-provider cross-check;
- live entitlement and latency acceptance.

### 5. Acceptance

v0.8 may be marked LIVE PASS only when all are true:

- licensed provider credentials are configured outside the browser;
- returned symbol and exchange match the requested instrument;
- timestamp convention has been verified for US, HK and CN;
- market session and holiday logic are verified;
- latest completed bar is compared with the provider’s own UI or reference response;
- price-change amount and percentage match the same reference close;
- stale, delayed and real-time data are labeled correctly;
- provider failure produces no bars rather than simulated replacement bars.
